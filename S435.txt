## 💡 Notes & Recommendations
- The mock `INDEX` is an in-memory list used for testing. In production, replace `add_to_index` with a robust search indexing implementation that supports asynchronous and durable updates (with retries and idempotency).
- The `SearchableMixin` uses `session.info`, which is recommended for session-scoped storage and avoids session-global mutability.
- For a distributed system with an actual search engine, atomicity and ordering should be implemented by a dedicated queue or index writing service (e.g., a message queue or indexer service).
- For production-grade concurrency and multi-process systems, use durable message queues (e.g., Kafka, RabbitMQ) and/or distributed locks rather than in-process locks.

## ⚠️ Known Limitations (and why we kept them)

- The `SearchableMixin` event handlers assume `Post` is the only searchable model in this minimal test scenario. To support multiple mixin classes, we'd enumerate all searchable models or expand the event handler to dispatch based on mapped classes or metadata.
