## 💡 Technical notes and reasoning
- Session safety: `session.info` is session-local, and with Flask-SQLAlchemy it is bound to the session object (scoped per thread). This prevents cross-thread leakage that arises when attaching attributes to the global `db.session` object.
- Event registration: Binding listeners to the `Session` class ensures hooks apply to all sessions created by SQLAlchemy session factory. This is a recommended approach versus attaching to a specific scoped session instance.
- Atomic index updates: The mock index is a Python list; without locks, concurrent appends could interleave or races could result in inconsistent views. The `INDEX_LOCK` ensures serial updates to `INDEX`.
- Tests: Each thread uses `app.app_context()` to ensure db connections/session are bound correctly to the thread.

## ⚠️ Warnings / Caveats
- There are deprecation warnings from SQLAlchemy for `Query.get()` — recommended to use `session.get()` moving forward. The tests still work, but you may want to update queries to use `db.session.get(Post, id)`.
- The mock index is an in-memory list; this demonstrates the behavior but would be replaced by a proper queue or message system in production to ensure ordering and durability.
